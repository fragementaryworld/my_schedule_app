# 工作生活

本机运行的个人计划管理工具，使用 Node.js 原生模块，无需安装第三方依赖。

## 启动

已在 Node.js 24 环境验证。Windows 推荐双击 `启动.vbs`：服务在后台运行并打开浏览器，不保留 CMD 窗口。旧入口 `启动.bat` 会转交无窗口启动后退出；如要避免批处理刚启动时的一闪，请使用 `启动.vbs`。也可在项目目录执行 `npm start` 查看前台运行日志，然后打开 <http://localhost:4321/>。

后台启动日志保存在 `data/startup.log` 和 `data/startup-error.log`（自定义 DATA_FILE 时位于该数据文件的目录）。若浏览器未打开，可查看日志，或运行 `npm start` 排查。结束后台服务请点击页面右上角「保存并结束服务」。无需安装启动依赖或修改系统配置；若系统禁用了 Windows Script Host，可继续使用 `npm start`。

数据保存在 `data/data.json`，自动备份为 `data/data.json.bak`。请勿同时用多个服务写同一份数据；如检测到外部修改，保存会报错并保留磁盘数据，请重启后继续。

## 保存与结束

右上角「保存」会提交当前内容和预计用时等编辑，再保存到磁盘。

切换页面前会提交尚未保存的正文和预计用时等编辑，失败时保留原页面和草稿。修改其他属性触发重绘时，也会先保存正文；旧页面迟到的请求不会覆盖当前页面。

「保存并结束服务」确认后会提交待保存的编辑、等待进行中的写入、保存数据并释放服务端口。成功后页面显示结束提示，可以关闭浏览器。保存失败时服务继续运行，页面显示错误；处理后可以重试。

重新使用时再次启动并刷新页面。结束按钮只关闭本项目服务，浏览器页面会保留。

## 今日计划

「今日计划」默认展示周视图，可切换月视图。点击日期，下方显示上午、下午、晚上和当天待安排。空的晚上分区隐藏，已完成任务折叠在底部；项目名或事务清单作为任务行的辅助提示。

任务只通过「所属清单」选择收集箱、工作事务、生活事务或具体项目，不再填写事务标签和项目分类。新任务默认放入收集箱，旧的无项目任务兼容到工作事务。灵感转换沿用同一选择；历史来源、分类、标签数据保留。

通过「安排任务」打开候选面板，可搜索并批量安排零散事项、持续任务和项目任务。当天截止的事项默认显示在当天待安排，并标记今日截止；持续任务保留日历跨度，明确安排后才进入当天列表。同一任务只出现一次。

安排面板按所属清单分区：收集箱、工作事务、生活事务，以及每个具体项目。各区有独立标题、任务数量、彩色边框和留白，项目颜色与日历一致。支持跨分区选择；搜索不会清空选择，底部会提示被搜索隐藏的已选任务。

时段选择不自动填具体时间；填写开始时间后，系统按开始时间归入上午（12:00 前）、下午（12:00–18:00 前）或晚上（18:00 起）。可以设置同一天内的结束时间，展开「具体时间轴」查看。时间重叠会提示，可调整或明确允许重叠。任务详情页也能调整安排。

任务可拖动跨时段、在无具体时间的任务之间排序，也可使用时段选择、上下移动按钮和「明天」按钮。切换时段会清除精确时间，预计用时保留；有具体时间的任务优先按时间排列。分区汇总已估算用时，并提示未估算数量。时间到达不会自动移动未完成任务。

日历和当天列表共用搜索与清单筛选。清单筛选支持多选，例如同时勾选工作事务和生活事务，也可以组合多个项目；未勾选时显示全部清单。搜索在所选清单中生效，切换周/月保留筛选条件；点击「全部清单」只重置清单选择，「清除筛选」同时清除搜索和选择。

新增任务使用所选日期；切换周/月保留所选日期，翻页同步更新。一个任务支持一个连续安排段，可用日历边缘拉伸或「调整日期或时间」中的结束日期设置跨天范围。区间内每天都会显示该任务，沿用相同的时段和具体时间；完成任务表示整项任务完成。整体改期会保留区间长度，不复制任务。明确安排的事件条只修改安排日期，不改变任务原日期或项目截止日期；尚未明确安排的原始日期事件则修改原起止日期。需要同一任务多个独立安排段时，可暂时拆成具体子任务。

当天看板以时段底色区分上午、下午、晚上和待安排，浅色与深色主题均适用。任务「⋯」菜单可点击外部或按 Esc 收起。

周/月日历中的任务统一采用彩色事件条，底色加深，完整边框、左侧色条和轻阴影加强轮廓；单日与跨天任务使用相同的文字和圆角。日历只展示标题、时间与简洁的重复标记；悬浮提示显示清单等信息，点击或按 Enter 进入详情。完成、取消完成和完成整个重复系列通过下方日期看板操作。

周／月日历可直接拖动任务标题或事件条本体改期，左右边缘分别调整开始和结束日期。月视图移动和拉伸均可跨周行；只有实际端点有拉伸把手，跨周裁切处显示延续箭头。拖动时预览连续区间并高亮落位日期，松手后才保存。鼠标和触控均适用，Esc 或移出日历后松手可取消，保存失败会还原预览并显示错误。也可在任务详情中编辑安排日期。

首页的今日任务数量与每日看板使用相同规则，包含当天安排和当天截止的项目任务及子任务。完成整个重复系列后，之后生成的实例保持完成；删除某次实例后不会再自动生成该次任务。

## WebDAV 数据同步

「启用 WebDAV 同步」为总开关，切换立即保存；关闭后停止启动、定时和手动同步，连接设置与恢复备份保留。重新开启后按原自动同步设置运行。原有「启动及定时自动同步」开关仍可单独控制自动同步，关闭它只保留手动同步。

在「数据与设置 → WebDAV 同步」填写已有 WebDAV 目录地址、用户名、密码或应用专用密码，保存设置后可「测试连接」或「立即同步」。同一批设备使用相同目录及文件名（默认 `schedule-app.json`）。目录需提前创建，服务需支持读取、写入及条件写入；覆盖已有文件要求服务器提供强 ETag。

默认开启启动及定时自动同步，每 5 分钟一次，可调整间隔。「启动」指浏览器打开应用页面；页面关闭后不自动同步。正在编辑时延后，传输期间暂时锁定编辑；下载成功后刷新当前页面。关闭自动同步后仍可点击「立即同步」。网络异常会显示原因，并在下一周期重试。

同步整份应用 JSON 备份，包括任务、项目、阅读、健身、灵感、备忘和偏好。首次远端文件不存在时上传；一端无业务数据时使用有数据的一端；首次两端有不同数据、两端都发生修改或曾同步的数据意外清空时，暂停自动同步，在设置中明确选择保留哪一端。不做逐条合并。通过上次同步指纹和条件写入避免覆盖其他设备的修改。

每次覆盖前保留恢复备份，最近 20 份可从同步设置导出，再通过原有数据导入功能恢复。连接设置、密码及同步状态保存在本机 `data/data.json.webdav.json`，恢复文件位于 `data/data.json.webdav-backups/`（自定义 DATA_FILE 时跟随该文件名）；它们不进入上传的备份。密码以明文存于本机配置文件，请保护该文件；HTTP 不加密传输，建议使用 HTTPS。更换服务器或账号后请重新填写密码。清除连接设置不会删除本机业务数据、远端文件或恢复备份。

## 备份与数据可靠性

导入前会验证备份结构和资源字段，补齐旧版缺失的集合并迁移内容。错误文件不会覆盖现有数据。服务端写入使用串行草稿事务：校验或写盘失败不会留下部分修改，成功提交后才返回成功响应。

API 只接受本机来源，拒绝其他网站及表单类型的数据写入。本机脚本携带请求体时请使用 `Content-Type: application/json`。

模块职责、兼容性和验证边界见 [架构文档](ARCHITECTURE.md)。

## 测试

运行 `npm test`。测试使用独立临时数据，不依赖个人数据。

隔离运行示例（PowerShell）：

```powershell
$env:DATA_FILE = "$env:TEMP\schedule-preview\data.json"
$env:PORT = '4322'
$env:NO_BROWSER = '1'
npm start
```
